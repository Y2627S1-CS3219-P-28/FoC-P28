# ADR-059 — Order-owned Report resolution saga

Approved by Yao Xiang on `order-service/admin-ui-linking`,2026-10-29, CHANGE-162. Report Service is absent; the user explicitly approves a guarded contract-stub implementation, durable migration, proposed peer contracts and configurable topics. No Report backend or GCP resources are changed. Live integration defaults disabled.

The initial resolve call is synchronous HTTP with the resolving admin's Firebase token and required reply. Order first commits a stable command/binding/lease while retaining the report-specific hold. It marks possible remote effect before the call. A confirmed matching Report resolution is followed by a short local transaction that releases only that report hold and saves the successful response atomically. No row lock spans network I/O and no user token is persisted. Same-key retries reuse the saved command/result and do not repeat the remote mutation.

Failure/uncertain response before local success chooses durable compensation in a separate transaction. A deterministic event ID plus command ID, report/order/requester/courier/admin IDs and a newer fencing generation go into the existing outbox. The existing after-commit dispatcher, bounded publication retries/FAILED retention and operator redrive apply. Broker ACK is not reversal confirmation. An authenticated, strictly bound Report result is atomically deduplicated in a new inbox; only a confirmed reversal/fence marks COMPENSATED. Conflicts remain RECONCILIATION_REQUIRED with the hold active. Lost results can republish the same compensation ID; exhausted publication remains retained for operators. Successful local release is terminal: lost responses or late failures cannot compensate committed success.

Proposed Report contract, explicitly a fixture rather than a verified peer: callback-free `PUT /api/reports/internal/order-resolutions/{commandId}`. Report must journal the operation's preimage/revision atomically with RESOLVED, enforce admin authorization, make same-key requests idempotent and reject conflicting bindings. Compensation restores only that operation's revision or creates an absent-operation fence; it must not overwrite newer admin work. An older delayed HTTP call cannot execute after compensation generation2 fences generation1. Report publishes a committed result through its own durable outbox. These safeguards are required even though reportId identifies the record.

New Order APIs: admin POST `/api/orders/admin/{orderId}/reports/{reportId}/resolve` with commandId/reply, and GET `/api/orders/admin/report-resolutions/{commandId}` for status. Coordination endpoints are absent when disabled. When enabled, the old direct hold-release HTTP route rejects with409, preventing bypass; the coordinator reuses the existing internal hold release in its success transaction. Existing admin cancel override, delivery progression, funds/penalty rules and other active holds are unchanged.

Additive Flyway V18 creates a separate Report resolution journal/inbox; existing Order/Credit command kinds and old migrations stay unchanged. Recovery joins the existing minute lifecycle pass as an independent DB-selected/per-command transaction, not a new whole-batch transaction. Separate Google OIDC Report push identity and exact subscription/type/version/ID checks protect the result receiver; unsigned delivery requires explicit local demo Auth/PubSub emulators. Reuse existing publisher factory/transport validator, not Credit journal tables or credentials.

Topics: `report-resolution-compensation-{local|dev|prod}-v1` and `report-resolution-compensation-result-{local|dev|prod}-v1`. Only Order configuration/.env.example and documentation are added; no bootstrap, deployment activation, subscription or IAM mutation. Report UI remains local sample/cloud Coming soon until real provider verification.


Verification2026-10-29: full reactor673 tests and existing coverage gates pass; Order PostgreSQL/HTTP/broker fixtures cover successful replay, local rollback, unknown response, stale lease/fence, same-ID re-publication, duplicate/mismatched results and reconciliation. Final API/security10 and saga9 targeted tests pass. Image/default-off/schema18 smoke and AsyncAPI checks pass. These fixtures do not verify a Report implementation or cloud delivery; rollout stays disabled.
