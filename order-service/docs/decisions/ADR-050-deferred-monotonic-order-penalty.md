# ADR-050 — Deferred monotonic Order penalty

Approved Yao Xiang, 2026-10-19, order-service/penalty-integration. Supersedes CHANGE-144 synchronous replacement and admin completion from CHANGE-137. Keep Report cards/layout/replies and ordinary requester/automatic completion.

Order owns a nullable appliedPenalty policy for the current courier assignment, with actor/reason/time audit. Apply penalty is an admin-protected transactional locked write on an assigned active order, including held orders; policy must be a report case from PenaltySystemPolicy.getCourierPenaltyCases(). It does not change lifecycle, release a hold, publish an event, or call User Service to change a score. Same command ID binds administrator/order/courier/version/policy/reason; exact retries return current Order. Stored maximum only increases; equal/lower submissions cannot clear or replace it. Another courier acceptance resets the current assignment's stored policy. Existing final per-attempt outcome records stay as append-only final-event evidence, not a score-replacement feature.

Requester and auto completion choose max(stored report penalty, factual delivery overdue penalty); if neither exists, successful-delivery reward. A penalty never also earns a reward. Existing historical V12 waiver is respected only for its overdue candidate, never to erase a stored report penalty; no new waiver operation exists. Courier accepted cancellation chooses max(stored penalty, ACCEPTED_TASK_CANCELLATION), preserving one final outcome/event per attempt, then clears stored current penalty when reopening. Admin cancellation chooses max(stored penalty, explicit selected additions) and NEVER consults overdue. No stored/selected penalty means refund only, no reward. No admin can waive an already stored penalty. Resolving a false-alarm report without applying a penalty allows normal completion after report-specific hold release.

Remove real/mock admin completion endpoint/button/service/DTO and adjustment endpoint/UI/synchronous User gateway/settings. No new adjustment topic or replacement contract is needed. Existing addition/deduction event DTOs/topics and Credit events remain unchanged. New endpoint POST /api/orders/admin/{orderId}/apply-penalty accepts commandId, expectedVersion, courierId, policy, reason; returns OrderResponse containing stored policy/amount/audit. Keep existing role annotation, NOWAIT row lock and pending-command guard. HTTP401/403 unauthorized,400 invalid policy/input,404 missing order,409 stale version/wrong courier/terminal/contention/bound-command conflict. UI local mock mirrors monotonic storage, live uses the real Order endpoint without any User replacement dependency.

V13 may already be applied, so do not alter/remove it or drop audit tables. Forward-only V14 adds nullable Order penalty/audit fields with constraints and preserves existing data. Retired adjustment rows/tables are historical only and need operator review if any previously enabled integration left pending requests; no silent replay or guessed score conversion. No sibling backend/shared .env/topic/cloud/CI changes. ADR-050 records the new design. TDD covers monotonic policy, no early event, completion highest/reward, admin cancel ignores overdue, retired routes, roles/rollback/idempotency and UI state.
